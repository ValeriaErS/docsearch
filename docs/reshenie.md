# Решение DocSearch

## Стратегия чанкования

Документы разбиваются на фрагменты с помощью умного чанкования:

1. **Разделение по заголовкам**: Текст разбивается на секции по заголовкам Markdown (`#`, `##`, `###`)
2. **Нарезка по предложениям**: Внутри каждой секции текст делится по предложениям
3. **Перекрытие**: При создании новых чанков последние предложения предыдущего чанка добавляются в начало нового (параметр `overlap_tokens` из конфига)
4. **Ограничение по токенам**: Максимальный размер чанка контролируется через `max_tokens`
5. **Реальные страницы PDF**: Для PDF-документов сохраняется точная страница каждого чанка на основе позиции в тексте

Такой подход позволяет сохранять смысловую целостность и не терять контекст на границах.

## Выбор моделей

### Эмбеддинги
Используется модель `text-embedding-nomic-embed-text-v1.5` через LM Studio. Выбор обоснован:
- Работает локально, не требует интернета
- Размер вектора 768, что даёт хорошее соотношение качества и производительности
- Поддерживается через OpenAI-совместимый API

### LLM
Для генерации ответов используется OpenRouter с моделью `openrouter/free`. Это позволяет:
- Получить доступ к разным моделям через единый API
- Использовать бесплатные модели для тестирования
- Легко менять модель через конфигурацию

## Схема поиска

1. **Эмбеддинг запроса**: Вопрос пользователя преобразуется в вектор
2. **Поиск в Qdrant**: Вектор сравнивается с векторами всех чанков через косинусную близость (приближённый поиск, ANN)
3. **Фильтрация**: Остаются только чанки с `score >= min_score`
4. **Сортировка**: Результаты сортируются по убыванию близости
5. **Top-K**: Берутся первые K результатов (задаётся через `top_k`)

Для тестирования качества есть режим сравнения с полным перебором (команда `compare`).

## Мультитенантность

Все документы и поиск изолированы по `user_id`. Каждый пользователь видит только свои документы. Фильтрация по `user_id` применяется на уровне Qdrant и дополнительно проверяется в коде.

## Mock-режим

Для автономного тестирования без внешних сервисов есть режим `provider: "mock"`:
- Используется `FakeVectorStore` вместо Qdrant
- Эмбеддинги генерируются на основе текста (bag-of-words)
- Демо и eval работают без интернета
- Запуск: `make demo` и `make eval`

## Формат промпта

Промпт для LLM строится так:

1. **Системная инструкция**: Требование отвечать только по документам и указывать источники
2. **Контекст**: Найденные чанки с указанием документа и страницы
3. **История**: Последние 4-5 сообщений из диалога
4. **Вопрос**: Текущий вопрос пользователя

Формат указания источников: `[источник: название_файла.pdf, страница N]`

## Обработка случая "нет ответа"

Если после фильтрации по `min_score` не осталось ни одного чанка, возвращается ответ: "В документации нет информации по этому вопросу". Это предотвращает галлюцинации LLM.

## Известные ограничения

1. Требуется запущенный Qdrant и LM Studio (кроме mock-режима)
2. Поддерживаются форматы: `.md`, `.txt`, `.pdf`, `.html`
3. История чата ограничена 50 сообщениями
4. Страницы PDF определяются по позиции в тексте (неидеально для сложных PDF)

## Идеи для улучшения

1. Подстроить параметры индекса Qdrant для ускорения поиска
2. Поддержка большего количества форматов (docx, xlsx)
3. Кэширование эмбеддингов
4. Асинхронная индексация
5. Поддержка потоковой передачи ответов (streaming)
